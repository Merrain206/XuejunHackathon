# 普通投资者 Evidence 扩展

> 状态日期：2026-10-03
> 当前产物：`cninfo.multicompany.expanded.v2.db`（候选库，不替换稳定库）

## 1. 目标与边界

本轮把动态问答从基础财务指标扩展到普通投资者常问的公司治理、审计、股东回报、员工与激励、供应链、关联关系、经营结构、研发和风险问题。目标是尽可能提高官方公告内问题的覆盖率，不是承诺任意问题必答。

仍然遵守 `No Evidence, No Claim`：每条新增 Evidence 必须是对应 PDF 页面的连续原文，最多 200 字符；后端只检索 `excluded=0` 的 Evidence；Claim、Signal 和 Chart 只能使用自己引用 Evidence 能支撑的内容。公告未披露、当前文档缺失或无法形成精确摘录时，系统必须部分回答或拒答。

## 2. 主题范围

`xray-backend/investor_topics.py` 是扩库和问题路由共用的单一主题目录，共 54 类：

- 公司治理与股东权利：董事会构成、董事提名、实际控制人、中小股东机制、独立董事、股东结构、董监高持股、股份质押、总股本。
- 审计、内控与合规：审计意见、审计机构、关键审计事项、内控意见、监管处罚、诉讼仲裁、对外担保。
- 股东回报与员工利益：历史分红、每股分红方案、分红政策、股份回购、员工持股计划、员工持股平台、股权激励、员工人数、董监高薪酬。
- 经营与供应链：劳务外包、劳务派遣、主要客户、主要供应商、关联方、关联交易、产品与主营业务、竞争地位、专利、研发人员、重大合同、子公司、并购、产品/研发管线、分业务收入、境外收入。
- 资产、债务、项目与风险：总负债、净资产、货币资金、商誉、减值、债务结构、募集资金、募投进展、政府补助、税收优惠、环保、安全生产、数据安全。

基础数据库原有的营业收入、归母净利润、经营现金流、毛利率、总资产、资产负债率等财务指标继续保留。复合问法会同时检索相关主题；若只有部分 Evidence，就只回答能证明的子问题。

## 4. 图表规则

模型只生成带 Evidence 引用的文字结构，不直接生成图表。后端在最终 Evidence 校验完成后确定性构建图表：

- 历史趋势问题使用折线图，最多 3 张。
- 最近一期多个指标使用柱状图；金额、比例、每股数据等不同单位分图展示。
- 一个问题最多返回 3 张图；一张图说不清的复合问题可以返回 2–3 张。
- 图表中的每个数值必须来自图表自己的 `evidence_ids`；金额统一换算为亿元，比例为 `%`，每股指标为元/股。

## 5. 已知边界

- 同行毛利率比较尚未实现。四家目标公司属于不同业务，不能被当作同行；要实现该问题，需要先确认同行口径，再采集同行公司官方披露。
- 审计机构“近三年是否更换”需要跨年度 Evidence 齐全；缺某一年时只能说明已检索年份，不能推断连续未更换。
- “假外包、真派遣”属于需要合同、人员管理和实际用工证据的判断。只有外包费用或派遣人数时，不得直接定性。
- “普通股东能分到多少”取决于持股数量、股权登记日和方案状态；Evidence 不足时只能给每股/每 10 股方案和计算口径。
- 当前只允许两类受控派生计算：净现比按同期间经营现金流净额 ÷ 归母净利润计算；持股分红按用户持股数 ÷ 方案基数股数 × 每基数股现金红利计算。两者都必须展示公式并引用完整输入 Evidence。

## 6. 复现与验证

扩库脚本始终复制输入库后写入新文件，不会原地修改输入库：

```powershell
.\xray-backend\.venv\Scripts\python.exe .\expand_investor_evidence.py `
  --src .\cninfo.multicompany.next.db `
  --dst .\cninfo.multicompany.expanded.v2.db
```

验证命令：

```powershell
.\xray-backend\.venv\Scripts\python.exe -m pytest .\test_expand_investor_evidence.py -q
.\xray-backend\.venv\Scripts\python.exe .\acceptance_check.py --db .\cninfo.multicompany.expanded.v2.db

cd .\xray-backend
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe -m pytest tests_real -q
.\.venv\Scripts\python.exe scripts\check_frontend_contract.py
```

`tests` 与 `tests_real` 必须分开进程执行，避免 `config.settings` 因导入顺序绑定到错误数据库。数据库文件均被 Git 忽略，不得提交或自动替换 `cninfo.db`。
