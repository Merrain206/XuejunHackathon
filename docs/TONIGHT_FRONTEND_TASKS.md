## 2. API 契约

继续使用唯一问答接口：

```http
POST /companies/{company_code}/ask
Content-Type: application/json

{"question":"最近营业收入和归母净利润表现如何？"}
```

现有 snake_case 契约保持不变。允许 Evidence 新增可选字段：

```json
{
  "verification_status": "verified | auto | pending"
}
```

要求：

- snake_case → camelCase 转换仍集中在 `src/lib/api.ts`。
- 运行时校验必须继续存在；可选字段若出现则校验枚举值。
- `source_url` 是裸 PDF URL，前端只追加一次 `#page=N`。
- 所有 Claim、Signal、Chart 引用的 Evidence ID 必须存在，否则整次响应降级。
- 后端动态回答没有图表时正常展示 Answer、Claim、Signal、Evidence。

## 3. Evidence 可靠度

不要仅凭域名把自动抽取 Evidence 标成“高”。建议规则：

- `verified` + 官方 HTTPS 来源 + 页码 + 原文 + 数字匹配：高。
- `auto` + 官方来源 + 页码 + 原文已由后端机械核验：中。
- `pending`、缺页码、缺原文或数字不匹配：待核验。

官方来源至少识别：

- `sse.com.cn` 及其子域名
- `cninfo.com.cn` 及其子域名

如果后端尚未返回 `verification_status`：

- 现有思看科技人工核验 Evidence 维持当前行为。
- 其他公司动态 Evidence 默认按“中”处理，不要误报人工核验。
